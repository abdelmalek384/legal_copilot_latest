## 1. General Authority for Amiri Press — official legislation and Gazette archive

**Subject:** Request for authorized digital access and reuse terms for Egyptian legislation

السادة/ الهيئة العامة لشئون المطابع الأميرية،

نعمل على تطوير Legal Copilot، وهو مشروع للبحث القانوني باللغة العربية يهدف إلى مساعدة المستخدمين في الوصول إلى التشريعات المصرية مع إظهار مصدر النص وتاريخ نشره وتعديلاته وحالته الزمنية.

نرجو إفادتنا بالوسائل المعتمدة للحصول على النصوص التشريعية وأعداد الجريدة الرسمية والوقائع المصرية، بما في ذلك أي أرشيف رقمي أو واجهة API أو تصدير جماعي مرخص أو خدمة اشتراك مناسبة لهذا الغرض.

ونرجو توضيح شروط كل استخدام من الاستخدامات التالية على حدة:

1. تنزيل النسخ الأصلية وحفظها في قاعدة بيانات خاصة ومؤمّنة.
2. استخراج النص العربي وفهرسته للبحث والاسترجاع.
3. حفظ بيانات النشر، ورقم العدد والتاريخ والصفحات، وربط كل تشريع بالتعديلات والإلغاءات والتشريعات المكملة.
4. استخدام الفهرس والمقتطفات المسترجعة داخل منتج بحث قانوني تجاري.
5. عرض مقتطفات محدودة للمستخدم مع الاستشهاد الدقيق ورابط المصدر.
6. الاحتفاظ بالنسخ التاريخية لأغراض تتبع التعديلات، مع توضيح أنها تاريخية عند اللزوم.
7. تحديث البيانات عند صدور تصحيح أو تعديل أو إصدار جديد.

كما نرجو بيان الرسوم والاشتراكات، وحدود الاستخدام ومعدلات الطلبات، ومتطلبات النسبة إلى المصدر، وآلية الحصول على التصحيحات والتحديثات، وأي قيود على إعادة النشر أو الاستخدام التجاري. وإذا كانت هناك رخصة أو موافقة مكتوبة مطلوبة، نرجو إرشادنا إلى إجراءات طلبها.

لن نبدأ أي تنزيل آلي أو جماعي قبل توضيح شروط الوصول والاستخدام والحصول على الموافقات اللازمة.

وتفضلوا بقبول فائق الاحترام،

## 2. Court of Cassation — judgment access and licensing

**Subject:** Request for authorized access to published judgments and legal principles

السادة/ محكمة النقض،

نعمل على تطوير Legal Copilot، وهو مشروع للبحث القانوني يهدف إلى مساعدة الباحثين والمحامين على العثور على النصوص القانونية والأحكام المنشورة مع الحفاظ على بيانات الاستشهاد بالمصدر.

نحترم شروط استخدام الموقع ولا نطلب تجاوز أي قيود تقنية أو اشتراكات أو ضوابط وصول. نرجو إفادتنا بما إذا كانت المحكمة توفر وسيلة رسمية مرخصة للحصول على بيانات الأحكام أو نصوصها، مثل واجهة API أو تصدير محدود/جماعي أو اتفاق ترخيص.

## 3. Source-register follow-up checklist

When a request is sent, record:

- [ ] Date sent, recipient/department, and copy of exact request.
- [ ] Reply date and evidence location.
- [ ] Whether the response covers exact source/document types and access methods.
- [ ] Separate permission decisions for download, preservation, extraction, indexing, model processing, commercial use, excerpts, and redistribution.
- [ ] Restrictions, subscription terms, rate limits, attribution, privacy rules, and expiration/renewal.
- [ ] Reviewer and date who interpreted the permission.
- [ ] Register status updated only to the narrow permission actually granted.

A generic “public access” response is not sufficient if it does not address the intended activity. Where the response is ambiguous, keep the status `permission_pending`.
